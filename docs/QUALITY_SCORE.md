# 品質目標

このプロジェクトの品質目標の正本。目標ごとに、測る項目、確かめ方、目標を守る検査の識別子を「目標」の節に書き、
領域と層ごとの現在の評価を「現在の評価」の節に書く。

検査の識別子は、`package.json` の `scripts` の名前そのもので、バッククォートで囲んだ識別子を、コンマと半角の空白 1 つで
区切って書く。人が確かめるだけの行は `-` と書く。表 2 の層のセルは、バッククォートで囲んだパスで書く。「目標」の節の表と
「現在の評価」の節の 2 つの表は、見出しの行の文字列と列の数を変えない（識別子と評価を機械的に読むため）。
この文書は `scripts/harness/drift-scan.sh`（定期の走査）が読む。表の見出しの行や列を変えるときは、同じ変更で走査も直す。

|---|---|---|---|
| 層の依存の向きが `ARCHITECTURE.md` のとおり | 違反の件数（0 を保つ） | `npm run check:arch` | `check:arch` |

| 整形・選別の振る舞いが試験で守られている | `src/curation/` と `src/services/` の試験が通る | `npm run test` | `test` |

## 現在の評価

評価の段階は次の 4 つである。

- `A`: 目標を満たし、機械的な検査が守っている。
- `B`: 目標を満たすが、守りの一部が人の確認である。
- `C`: 目標を一部満たさない、または確かめ方が無い。
- `D`: 目標を満たさない。

見直しの目安: 90 日

評価は、評価したコミットでの `npm run check` の段ごとの結果と、`ARCHITECTURE.md` の記述から、実装の担当が書き、
利用者が確かめる。評価した日から見直しの目安の日数が過ぎたら、評価し直す。

表 2 の「人が確かめる決まりの数」は、`ARCHITECTURE.md` で「レビューで人が確かめる」とした次の 4 つの決まりのうち、
対象にその層のファイルが入るものの数である。

- 決まり 1: `templates/` と `src/` の間の依存のうち、モジュールの名前を変数で組み立てた `import()` や `require()` と、
  引数の文字列で書いたパス（`ARCHITECTURE.md` の「層と責務」の `templates/` の段落）。対象は 8 層と `templates/`。
- 決まり 2: 不変条件 1 と 2 の、別名を経由した書き方（不変条件 2 の末尾）。対象は `src/ports/` を除く 7 層と `templates/`
  （`src/ports/` は通信と現在時刻を使ってよい層のため）。
- 決まり 3: 不変条件 5 の、ESLint が止められない書き方での外部のスクリプトの読み込み。対象は 8 層と `templates/`。
- 決まり 4: HTML の文字列を画面に入れる書き方のうち、ESLint が止められない形（「将来の作りの注意」の HTML の項）。
  対象は 8 層と `templates/`。
