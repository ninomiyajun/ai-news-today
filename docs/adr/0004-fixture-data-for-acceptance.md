# 0004 受け入れ確認のための確認用のデータの切り替え

## 背景

ハーネスに、受け入れ確認（動いているアプリをブラウザで操作して、計画の完了の条件を 1 件ずつ確かめ、記録を書く独立の担当）を
入れることにした。担当はコードを書き換えない。ところが、このアプリは情報源の取得をまだ作っておらず
（`src/composition/runtime.ts` の情報源が空）、起動した画面には「表示できる記事はまだありません。」だけが出る。
これまでの画面の確認（`docs/exec-plans/completed/2026-10-06-x-post-embed.md`）は、確認のときだけ `runtime.ts` を一時的に
書き換えていたが、受け入れ確認ではその方法が使えない。また、本物の情報源ができた後も、外部の応答と現在時刻しだいで
画面が変わると、同じ基準を毎回同じ結果で確かめられない。

## 判断

- **確認用のデータを使うかの判定と選択を、組み立ての層（`src/composition/runtime.ts`）に置く。** 本物の実装を選ぶのは
  この層だけという既存の責務（`ARCHITECTURE.md`）に合う。判定は `isFixtureMode` の 1 つの関数にまとめ、真のとき、
  記事の取得には `staticSource` と `fixedClock` を、X の埋め込みの取得には `fixtureHttpClient` を選ぶ。この層は選ぶだけで、
  データは持たない。
- **データは `src/sources/fixture.ts` の 1 ファイルにまとめる。** 決まった記事、基準の時刻、X の oEmbed の決まった応答を置く。
  記事には X の投稿の URL を含めない。含めると画面に埋め込みが出て、ブラウザが外部のスクリプト（`widgets.js`）を読みに行くためである。
- **判定は、環境変数 `AI_NEWS_FIXTURE` が `sample`、かつ `NODE_ENV` が `production` でないときだけ真にする。** 本番の起動で
  誤って効くことを防ぐためである。`NODE_ENV` は、実行時の値と、`next build` がビルドの時点の値に固定する直接の参照
  `process.env.NODE_ENV` の両方を見る。実行時の値だけでは、本番の build を `NODE_ENV=development` を付けて `next start`
  したときに効いてしまうためである。変数の名前に `NEXT_PUBLIC_` は付けない（ブラウザへ渡す値ではない）。
- **確認用のデータのときは、画面の上に「確認用のデータで表示中」を出す。** 開発用の起動で環境変数を付け忘れた、または
  付けたままにした取り違えを、人と受け入れ確認の担当の両方が画面で見分けられるようにするためである。判定の結果は
  画面の層が組み立ての層から受け取り、表示の部品（`src/ui/FixtureNotice.tsx`）に渡す。
- **方針: 本物の情報源ができたら、`staticSource` をやめ、本物の情報源を `fixtureHttpClient`（記録した応答）と `fixedClock` で
  動かす形へ移す。** 取得と選別の新しいコードも、受け入れ確認で通るようにするためである。

## 検討した代わりの案

- 本物の情報源だけで確かめる: 外部の応答と時刻で結果が変わり、外部へ通信するので採らない。
- 確認のたびに `runtime.ts` を書き換える（これまでの方法）: 受け入れ確認の担当はコードを書き換えないので使えない。
- `NODE_ENV` で絞らず環境変数だけで切り替える: 本番の起動に環境変数が残ると、決まった記事が本物のように出るので採らない。
- 画面に表示を出さない: 環境変数の付け忘れと付けたままを画面で見分けられないので採らない。

## 結果

- `AI_NEWS_FIXTURE=sample` を付けて `next dev` で起動すると、外部へ通信せず、毎回同じ記事が同じ順で出る。受け入れ確認は
  コードを書き換えずに画面を確かめられる。
- 本番の起動（`NODE_ENV=production`）では、環境変数があっても確認用のデータは使わない。
- 通常の経路（`createRuntimeDeps` の本物の側）に情報源を足したときは、同じ変更で確認用の経路（`src/sources/fixture.ts` と
  `createRuntimeDeps` の確認用の分岐）にも対応を足す。足し忘れには、`src/composition/runtime.test.ts` の試験
  「情報源は空で、本物の時計を使う（情報源を足したら、確認用の経路にも対応を足す）」が落ちることで気づく（その試験の期待値を
  直す前に、確認用の経路を直す）。
- 情報源を足すときは、確認用のデータも同じ変更で見直す（上の方針）。それまでは、確認用のデータで通るのは画面と選別と表示の
  コードだけで、取得のコードは通らない。
