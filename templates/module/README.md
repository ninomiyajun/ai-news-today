# モジュールのひな形

新しいモジュール（実装のファイルと、その試験のファイルの 1 組）を足すときの出発点。形だけを置いてあり、処理の中身は
入れていない。

## 入っているもの

| ファイル | 中身 |
|---|---|
| `ExampleLabel.tsx` | 表示の部品の最小の形。受け取った値を表示するだけである |
| `ExampleLabel.test.tsx` | その試験の最小の形 |

## 使い方

1. 置く層を決める（下の「置いてよい層」）。
2. 2 つのファイルを、その層のディレクトリへ写し、ファイルの名前と、中の名前（`ExampleLabel`）を、作るものに合わせて変える。
3. 試験のファイルの import を、`./ExampleLabel` から `@/<層の名前>/<ファイルの名前>` の形に直す（`src/` の下の既存の試験と
   同じ形）。
4. 試験に、作るものの振る舞いを具体的な入力と出力で書いてから、実装を書く。
5. `npm run check` を通す。

このディレクトリのファイルは、`npm run lint` と `npm run typecheck` の対象になる。`npm run test` は `src/` の下の試験だけを
実行するので、ここに置いたままの試験は実行されない。

## 置いてよい層

- 層の一覧と、各層の責務は、`ARCHITECTURE.md` の「層と責務」の表にある。`src/` の直下に、この表に無い
  ディレクトリやファイルを置かない（`npm run check:arch` が失敗にする）。
- このひな形は、表示の部品の層（`src/ui/`）の形で書いてある。ほかの層に置くときは、同じ層の既存のファイルの形に合わせる。
- 層を足すときは、ひな形を写す前に、`ARCHITECTURE.md` の「中核的な原則」に従って、設計の正本と検査の規則を直す。

## 守る決まり

- このディレクトリのひな形は、`src/` の何も import せず、それだけで型の検査が通る形に保つ。`src/` の中身が変わっても、
  ひな形が壊れないためである（`ARCHITECTURE.md` の「層と責務」）。アプリのコードからも、ここを import しない。
- 各層が import してよい層は、`ARCHITECTURE.md` の「依存の向き」の表にある。
- どの層でも守る決まりは、同じ文書の「不変条件」にある。
- 検査のコマンドと、秘匿値と個人情報の決まりは、`AGENTS.md` にある。
- 構成やインターフェースを変える作業では、先に計画を書く（`docs/PLANS.md` の「計画をファイルに書く条件」）。
