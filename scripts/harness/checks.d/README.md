# 追加の検査の口（`scripts/harness/checks.d/`）

このプロジェクトだけの文書の検査を置く場所。文書の検査の本体（`scripts/harness/check-docs.sh`）は、どのプロジェクトでも
同じ中身の写しなので、手で直さない。プロジェクト専用の検査は、本体を直さずに、ここへファイルを足す。

## 決まり

- 1 つの検査を 1 つのファイル `<名前>.sh` にする。本体は、名前が `.test.sh` で終わらない `*.sh` を、名前の順に 1 つずつ実行する。
- ファイルの 2 行目以降の冒頭の注釈に、`# 検査の名前: <短い名前>` の行をちょうど 1 行書く。名前は、本体の
  `--print checks` の出力と、`AGENTS.md` の検査のコマンドの表の括弧書きに使う。
- 本体は `bash <ファイル>` で呼ぶ。作業ディレクトリは検査する根で、標準入力は `/dev/null`。環境変数 `HARNESS_ROOT`（検査する
  根）と `HARNESS_ENGINE_DIR`（本体の置き場）を渡す。
- 終了コード: 0 は合格。1 は不合格で、出力の `check-docs: NG: ` で始まる行の数を、本体の件数に足す（無ければ 1 件）。
  直し方は、その次の行に `  直し方: ` で書く。ほかの終了コードは、実行できなかった 1 件の失敗になる。
- シンボリックリンクと、名前の行の無いファイルは、本体が失敗にする。
- 早期通知（`scripts/harness/notify.sh`）から別の作業ツリーを検査するときも、ここにあるのは起動元の検査だけを実行する。
  検査は、検査する根のファイルを文書として読むだけにし、そこのスクリプトを実行しない。
- 試験は同じ名前の `<名前>.test.sh` に書く。文書の検査の試験（`scripts/harness/check-docs.test.sh`）が最後に順に流す。
- 検査を足したり変えたりしたら、検査の由来の記録に行を足す（`AGENTS.md` の文書の地図の「検査の由来の記録」）。

## 本体へ移すとき

どのプロジェクトにも役立つ検査は、規約の正本（project-harness-init の `assets/harness/`）へ移す。移した後は、ここのファイルを
消し、導入済みのプロジェクトの更新で写しを置き換える。
