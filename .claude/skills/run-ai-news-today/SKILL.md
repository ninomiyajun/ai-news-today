# ai-news-today の起動・確認・停止

AI に関する今日のニュースを 1 画面（`/`）に表示する Next.js のアプリ。画面はサーバーで描くので、`curl` で HTML を取って
確かめられる。パスはすべてリポジトリの根からの相対である。

## 前提

- Node は 26 以上（`package.json` の `engines`、`.nvmrc`）。依存は `npm ci` で入れてある。
- **ポートは引数で選ぶ（以下 `<ポート>`）。3100 以上を使い、3000 は使わない。** 3000 は利用者が普段の `npm run dev` で使う。
- 待ち受けは `127.0.0.1` にだけ置く（`-H 127.0.0.1`。`AGENTS.md` の決定）。

## 確認用のデータ

環境変数 `AI_NEWS_FIXTURE=sample` を付けて `next dev` で起動すると、外部へ通信せず、決まった記事と決まった時刻で
画面を描く（`src/sources/fixture.ts`。理由は `docs/adr/0004-fixture-data-for-acceptance.md`）。このとき画面の上に
「確認用のデータで表示中」が出る。**画面を確かめるときは、確認用のデータで起動するのを主にする。** 結果が毎回同じに
なり、外部の応答と現在時刻に左右されないためである。本番の起動（`NODE_ENV=production`）では、環境変数を付けても効かない。

## 起動と確認

1. そのポートで何も待ち受けていないことを確かめる。何も出ず終了コード 1 なら空いている。何か出たら、そのポートは
   使わず、別のポートを選ぶ（ほかの人のサーバーにつないで確かめた気にならないため。自分で起動したもの以外は止めない）。

   ```bash
   lsof -nP -iTCP:<ポート> -sTCP:LISTEN
   ```

2. 確認用のデータでサーバーを起動する。エージェントは Bash の `run_in_background` で起動し（`&` は付けない）、
   返ったタスクの ID を控える。

   ```bash
   AI_NEWS_FIXTURE=sample npx next dev -H 127.0.0.1 -p <ポート>
   ```

   確認用のデータなしで起動するときは、環境変数を付けない（今は情報源が無いので、記事は出ない）。

   ```bash
   npx next dev -H 127.0.0.1 -p <ポート>
   ```

   **作業ディレクトリがリポジトリの外のとき**（`cd` で移れない担当など）は、次のどちらかの形で起動する。`<リポジトリの根>` は
   このリポジトリ（または worktree）の根の絶対パスに置き換える。どちらも、作業ディレクトリをリポジトリの外にした状態で、
   確認用のデータの画面（手順 4）が出ることを確かめてある。`npm` の形は `package.json` の `dev`（`-H 127.0.0.1` を含む）を使う。

   ```bash
   AI_NEWS_FIXTURE=sample npm --prefix <リポジトリの根> run dev -- -p <ポート>
   ```

   ```bash
   AI_NEWS_FIXTURE=sample <リポジトリの根>/node_modules/.bin/next dev <リポジトリの根> -H 127.0.0.1 -p <ポート>
   ```

   この形でも、`.next/` はリポジトリの根の下に作られ、止め方（下の「止め方と、止まったことの確かめ方」）と落とし穴は同じである。
   止めた後の差分の確認は `git -C <リポジトリの根> status --short` で行う。

3. 起動の完了を、回数と全体の時間の両方に上限のある再試行で待つ（再試行は 30 回まで、待ちの全体は 120 秒まで、
   1 回の要求は 60 秒まで。最初の要求は画面のコンパイルを待つので長くかかる）。`200` が出れば起動している。
   上限まで待っても `200` が出なければ、手順 2 の出力のファイルを読んで原因を確かめる（下の「うまくいかないとき」）。
   プロキシの設定が環境にあっても 127.0.0.1 へ直接つなぐよう、curl にはどれも `--noproxy '*'` を付ける。

   ```bash
   curl -s --noproxy '*' -o /dev/null -w '%{http_code}\n' --retry 30 --retry-delay 2 --retry-connrefused --retry-max-time 120 --max-time 60 http://127.0.0.1:<ポート>/
   ```

4. 画面を確かめる。確認用のデータの起動では、「確認用のデータで表示中」の文言と、`[確認用]` で始まる決まった記事が
   点数の高い順に出る。記事の題と点数の期待する値は `src/sources/fixture.ts` の説明にある。

   ```bash
   curl -s --noproxy '*' --max-time 60 http://127.0.0.1:<ポート>/ | grep -oE '確認用のデータで表示中|<h1>[^<]*</h1>|\[確認用\][^<"]*' | head -n 20
   ```

   **確認用のデータで起動したのに「確認用のデータで表示中」が出ないときは、確認用のデータが使えない環境である
   （環境変数が届いていない、本番の build で動いている、など）。そのまま画面を確かめ続けず、確認を止めて、起動の
   コマンドと手順 2 の出力のファイルの該当の行を添えて報告する。** 確認用のデータでない画面で確かめた結果は、
   決まった記事を前提にした基準の証拠にならないためである。

   確認用のデータなしの起動では、文言は出ず、「表示できる記事はまだありません。」が出る。

5. サーバーの記録（要求ごとの `GET / 200 in ...ms` と、サーバー側の例外）は、手順 2 のタスクの出力のファイルに出る。
   画面が 500 のときは、そこにスタックトレースがある。

## 止め方と、止まったことの確かめ方

1. 止める。`run_in_background` で起動したときは、手順 2 のタスクの ID を TaskStop に渡す。それ以外の方法で起動したときは、
   起動した者が止める。自分で起動したものだけを止める。
2. 止まったことを確かめる。次の 2 つがどちらも成り立てば止まっている。

   ```bash
   curl -s --noproxy '*' -o /dev/null -w '%{http_code}\n' --max-time 3 http://127.0.0.1:<ポート>/
   ```

   つながらず `000` が出て、終了コードが 7 になる。

   ```bash
   lsof -nP -iTCP:<ポート> -sTCP:LISTEN
   ```

   何も出ず、終了コードが 1 になる。止まらなかったときは、残っている待ち受けの pid と、タスクの ID を報告に書く。

## 落とし穴

- **同じ worktree で開発用のサーバーが既に動いていると、Next.js は 2 つ目を起動せずに終わる**（出力に
  「Another next dev server is already running.」と出る）。ポートを変えても同じである。既に動いているサーバーは、
  環境変数やコードが自分の確かめたいものと違いうるので、それにはつながない。別の worktree を作って、そこで起動して確かめる。
- 取得した HTML には、正常な 200 の画面でも「404: This page could not be found.」の文字列が含まれる（Next.js が
  not-found の部品を画面のデータとして埋め込むため）。成否は HTTP の状態と、画面の中身（文言、記事）で判定し、
  HTML の全体を「404」で検索して判定しない。
- `/` は要求のたびにサーバーで描く（`src/app/page.tsx` の `dynamic = "force-dynamic"`）。コードを変えた後は、
  再起動せずに `curl` し直せば新しい結果が出る。環境変数を変えたときは、止めて起動し直す。
- `next dev` は `AGENTS.md` の `nextjs-agent-rules` の区画を書き戻すことがある。止めた後に `git status --short` で
  差分を見る。

## うまくいかないとき

| 症状 | 対処 |
|---|---|
| 手順 1 で何か出る | そのポートは使われている。別のポートを選ぶ。自分で起動したもの以外は止めない |
| 手順 2 の出力に「Another next dev server is already running.」 | 上の落とし穴のとおり、別の worktree で確かめる |
| 手順 3 が上限まで待っても `200` にならない | 手順 2 の出力のファイルを読む。コンパイルの誤りやポートの取り合いがそこに出る |
| 画面に「確認用のデータで表示中」が出ない | 手順 2 のコマンドのとおりに起動したかを見直す（環境変数の付け忘れ、`NODE_ENV=production`、本番の build）。手順 2 のとおりでも出なければ、手順 4 のとおり確認を止めて報告する |
